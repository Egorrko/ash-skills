# The starter

`starter/` is a Phoenix + Ash + LiveVue project named `AppTemplate`. `bin/new-app` copies it, renames it and makes it runnable. It carries every `INSTALLER_DEFECTS.md` workaround, so a new project inherits none of those defects.

## Contents

- Generated by `igniter.new` with phx.new 1.8.17, Ash 3.38, ash_postgres, ash_phoenix, ash_oban, oban_web, usage_rules, then live_vue 1.2.3 with phoenix_vite 0.6.1 and quickbeam SSR. Exact versions are in `mix.lock` and `package-lock.json`.
- Component layer: reka-ui, the shadcn-vue `components.json`, `assets/lib/utils.ts` (`cn`), the theme in `assets/css/app.css` (with `@source "../components"`), and the primitives button, badge, card, input, switch.
- Quality harness (`STACK_POLICY.md`, "Quality harness"), all seven parts: live_vue_contract with strict mode and coverage; `vue-tsc` strict; vitest; oxlint, eslint, stylelint, knip and dependency-cruiser through `npm run lint:all`; credo with the project checks in `credo/checks/` and boundary on `<App>`, `<App>Web` and the application; `mix precommit` as the gate; `bin/shot.mjs` for screenshots.
- `/health` plug ahead of the endpoint stack, without a database call.
- Dev ports from `PORT` and `VITE_PORT`, so two copies of the project run side by side.
- `.claude/`: the composed usage_rules skills, the skill-reminder hook and its settings.
- Runtime artefacts for both profiles: `Dockerfile`, `.dockerignore` and `deploy/swarm/` for a container; `deploy/native/app_template.service` for a release under `systemd --user`. B4 keeps the one §12 names.
- `bin/verify`: the gate, the prod build, the release booted against a scratch database until `/health` answers 200; `--docker` adds the image build.

Not included, written per project: `CLAUDE.md`, `.claude/skills/next-slice/`, `README.md`, the domain, the dev login.

## Provenance

Built on 2026-11-25 from the Starbase bootstrap (`/new-ash-project` + `/ash-bootstrap` 0.2.3), whose B3 turned each harness part red on its planted mistake: a stray prop to a `<.vue>` tag, a type error in a component, a floating promise in `.vue` and `.ts`, `@apply` in `app.css`, an unused export, `Repo.all` inside a domain, a domain without `use Boundary`, a reference from the core to `<App>Web.Endpoint`. The copy was renamed, made port-generic and checked by `new-app` + `bin/verify` on two names (one sorting before `Phoenix`, one after, for credo's alias order): both green.

## Refresh

Monthly, or when a stack package releases a major version:

1. Follow `MANUAL_BOOTSTRAP.md` M1–M3 into a scratch project named `app_template`, with exactly the starter's feature set (`ash_oban`, `oban_web`, `live_vue`), applying `INSTALLER_DEFECTS.md` and recording which entries still reproduce.
2. Carry over what the starter adds beyond the generators: `/health`, the port-generic config, the runtime artefacts, `bin/verify`, the split alias group in `lib/app_template_web.ex`.
3. Replace `starter/` with it, excluding `_build`, `deps`, `node_modules`, `priv/static/assets`, `log`.
4. `bin/new-app` into two scratch names (`demo_shop`, `zulu_app`), `bin/verify` in each: both green. Then drop their databases.
5. Update the versions above and in `INSTALLER_DEFECTS.md`, bump the plugin version.
